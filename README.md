# CityPortal — движок городского портала на PHP + MySQL

**CityPortal** — лёгкий движок для местного издания: новости, афиша, кино, погода, онлайн-радио и удобная админ-панель.
Подходит для **любого города, газеты или интернет-СМИ**: название, город (в трёх падежах), меню, цвета, логотип и тексты настраиваются из админки, без правки кода.
Эталонная установка — «Твой Кореновск».

**Без рекламы, без аналитики, без cookie и без сбора данных о читателях** (подробнее — `docs/PRIVACY.md`). Composer и Node.js не нужны — достаточно обычного PHP-хостинга.

## Возможности

**Для читателей**
* Новости с рубриками, тегами, поиском, галереями; афиша событий с архивом; расписание кино; прогноз погоды; онлайн-радио.
* **Радио не прерывается при переходах** по сайту: страницы подгружаются «плавно», шапка и плеер не перезагружаются.
* Кнопка **«Показать ещё»** и обычные номерные страницы — на выбор читателя.
* Светлая / тёмная / системная тема, mobile-first вёрстка (без горизонтальной прокрутки от 320 до 1920 px), фокус с клавиатуры, контраст WCAG AA, шрифты хранятся локально, изображения WebP с `srcset`.

**Для редакции**
* Новости: черновик → проверка → публикация, планирование, закрепление, теги с подсказками, галерея, живой SEO-чек-лист.
* Афиша, страницы, рубрики, ссылки и сервисы, **меню сайта**, **блоки на сайте**, **страницы разделов**.
* Медиатека: WebP/JPEG-варианты, drag&drop, защита от дублей по содержимому файла.
* Роли (администратор, редактор, автор), 2FA, журнал действий, резервные копии, проверка безопасности сервера.
* Массовые действия с **закреплённой снизу панелью** — она появляется, как только отмечена хотя бы одна запись.
* Адаптивная админка: на смартфоне меню закрывается по нажатию на фон, крестик, Esc и при переходе по ссылке.

**Для SEO**
* `sitemap.xml`, Google News, RSS и RSS для Яндекс Новостей/Дзен, `robots.txt`, `llms.txt`, IndexNow, JSON-LD, Open Graph, 301-редиректы — всё создаётся и обновляется автоматически.

## Требования

| | Минимум | Рекомендуется |
|---|---|---|
| PHP | 8.2 | **8.4 или 8.5** (8.2 получает только исправления безопасности до 31.12.2026) |
| База данных | MySQL 8.4 / MariaDB 10.11 | MariaDB 11.4 LTS или MySQL 8.4 LTS, кодировка `utf8mb4` |
| Расширения PHP | `pdo_mysql`, `mbstring`, `dom`, `openssl`, `fileinfo` | дополнительно `gd`, `curl`, `exif` |
| Веб-сервер | Apache (`mod_rewrite`) или Nginx + PHP-FPM | HTTPS обязателен |

Что даёт каждое расширение:

| Расширение | Без него |
|---|---|
| `gd` | нельзя загружать фото и создавать иконки сайта |
| WebP в GD | фото сохраняются в JPEG/PNG |
| `curl` | не работают погода и IndexNow |
| `exif` | не учитывается ориентация фото с телефона |

Установщик **ничего не блокирует**: проверки сервера — только подсказки.

```bash

```

## Установка подробно

### Шаг 0. Подготовка

1. **Хостинг или сервер** с PHP 8.2+ и MySQL/MariaDB (см. [Требования](#требования)).
2. **Домен с HTTPS** (на большинстве хостингов сертификат Let's Encrypt включается в панели в один клик).
3. **Пустая база данных** в кодировке `utf8mb4` и пользователь с правами на неё (создаётся в панели хостинга или в phpMyAdmin). Запишите: хост, имя базы, логин, пароль.
4. **Файлы проекта.** Распакуйте архив и загрузите содержимое по FTP/SFTP или через файловый менеджер хостинга.
5. **Корень сайта — папка `public/`.** В панели хостинга найдите пункт «Корневая папка сайта» (Document Root) и укажите `.../public`.
   Если изменить корень нельзя — оставьте всё как есть: запасной `.htaccess` в корне перенаправит запросы в `public/` и закроет служебные папки (`app`, `config`, `database`, `storage`, `bin`, `tools`, `docs`).
6. **Права на запись** нужны папкам `config/`, `storage/` и `public/uploads/`. На обычном хостинге они выставлены по умолчанию; на VPS:
   ```bash
   chown -R www-data:www-data config storage public/uploads
   chmod -R u+rwX config storage public/uploads
   ```

### Способ 1. Мастер установки в браузере (рекомендуется)

Откройте сайт в браузере — мастер запустится сам. Он состоит из шести шагов:

| № | Шаг | Что делать |
|---|---|---|
| 1 | **Проверка сервера** | Посмотрите версии PHP и расширений, права на запись, HTTPS. Красные пункты — подсказки, а не запрет |
| 2 | **База данных** | Введите хост, имя базы, логин и пароль. Кнопка «Проверить подключение» ничего не устанавливает, но сразу покажет ошибку: неверный пароль, нет базы, нет прав `CREATE`, устаревшая версия СУБД |
| 3 | **Сайт и город** | Название, адрес сайта, адрес админки (кнопка «Случайный» подберёт неочевидный), город в трёх падежах, регион, координаты, часовой пояс, ключ WeatherAPI |
| 4 | **Набор данных** | «Чистый сайт», «Данные города Кореновск» или «Кореновск + демо-материалы» ([см. профили](#профили-данных)) |
| 5 | **Администратор** | Логин, e-mail, пароль (от 10 символов; есть генератор надёжного пароля) |
| 6 | **Издание** | Издатель и публичный e-mail (можно заполнить позже) |

Мастер создаст таблицы, страницы «О редакции», «Контакты», «Редакционные принципы», SEO-файлы, ключ IndexNow и файл `config/config.php`.
После установки войдите в админку по адресу, который вы выбрали на шаге 3, и пройдите список «Что сделать дальше» на финальном экране.

> Если папка `config/` недоступна для записи, мастер покажет готовый текст `config/config.php` — сохраните его вручную в этот файл.
> Мастер отключается сам: при наличии `config/config.php` он больше не запускается.

### Способ 2. Консоль

Подходит для VPS и автоматизации. Все параметры передаются переменными окружения:

```bash
DB_NAME=tk DB_USER=tk DB_PASS='пароль' SITE_URL=https://example.ru \
ADMIN_USER=admin ADMIN_EMAIL=me@example.ru ADMIN_PASS='длинный-пароль-12+' \
PROFILE=empty SITE_NAME='Новости Города' \
CITY_NAME=Город CITY_NAME_IN='в Городе' CITY_NAME_OF=Города \
CITY_LAT=55.75 CITY_LON=37.62 TZ=Europe/Moscow WEATHER_KEY=ваш_ключ \
CONTACT_EMAIL=redakciya@example.ru \
php bin/install.php
```

| Переменная | Назначение |
|---|---|
| `DB_NAME`, `DB_USER`, `DB_PASS` | доступ к базе данных |
| `SITE_URL` | канонический адрес сайта без слэша на конце |
| `ADMIN_USER`, `ADMIN_EMAIL`, `ADMIN_PASS` | первый администратор |
| `PROFILE` | `empty`, `korenovsk` или `demo` (по умолчанию `korenovsk`) |
| `SITE_NAME` | название издания |
| `CITY_NAME`, `CITY_NAME_IN`, `CITY_NAME_OF` | город: «Город», «в Городе», «Города» |
| `CITY_LAT`, `CITY_LON`, `TZ` | координаты для погоды и часовой пояс |
| `WEATHER_KEY` | ключ WeatherAPI.com (необязательно) |
| `CONTACT_EMAIL` | публичный e-mail редакции |

### Способ 3. Вручную через phpMyAdmin

1. Импортируйте `database/schema.sql` (вкладка «Импорт», кодировка `utf8mb4`).
2. По желанию: `database/seed.sql` (демо-статьи), затем `database/korenovsk.sql` (данные города).
   Порядок важен: **`seed.sql` — до `korenovsk.sql`**.
3. Скопируйте `config/config.sample.php` в `config/config.php` и заполните БД, `app.url`, `app.key` (64 случайных hex-символа):
   ```bash
   php -r "echo bin2hex(random_bytes(32));"
   ```
   Файл `installed.lock` не нужен: сайт считается установленным, когда есть `config.php`.
4. Создайте администратора вставкой строки в таблицу `users` (роль `admin`). Хэш пароля:
   ```bash
   php -r 'echo password_hash("пароль", PASSWORD_ARGON2ID);'
   ```
5. Создайте базовые страницы:
   ```bash
   php -r 'require "app/bootstrap.php"; echo App\Support\BasePages::install();'
   ```

Способ 3 самый трудоёмкий — по возможности используйте способ 1.

### Профили данных

| Профиль | Что внутри |
|---|---|
| `empty` | Таблицы, меню, страницы «О редакции», «Контакты», «Принципы». Ничего о Кореновске — **подходит для любого города** |
| `korenovsk` | `empty` + падежи и координаты города, рубрики, страницы «О Кореновске» и «Экстренные службы», ссылки на сайты администраций |
| `demo` | `korenovsk` + 11 демонстрационных статей с фото и ссылки сервисов |

`database/korenovsk.sql` можно запускать и на готовом сайте повторно: он обновляет только настройки города, а рубрики, страницы и ссылки добавляет, лишь если их ещё нет. Факты о городе взяты из открытых источников — проверьте их перед публикацией.

## Настройка веб-сервера

### Apache и обычный хостинг

* Нужен включённый `mod_rewrite`. Правила уже лежат в `public/.htaccess` (и запасные — в корневом `.htaccess`).
* Лимиты PHP заданы в `public/.user.ini` (загрузка файлов до 16 МБ, `memory_limit` 256 МБ и т. д.). Файл читается автоматически на PHP-FPM/CGI, обновление — до 5 минут.
  Если у вас `mod_php`, задайте те же значения в `php.ini` или через `php_value` в `.htaccess`.
* Включите HTTPS и перенаправление с `www` на основной домен (за него также отвечает `enforce_host` в конфиге).

### Nginx + PHP-FPM

Готовый пример — [`nginx.conf.example`](nginx.conf.example). Основное:

```nginx
server {
    listen 443 ssl http2;
    server_name example.ru;

    root /var/www/site/public;          # корень — именно public/
    index index.php;
    client_max_body_size 16m;

    location ~ /\.(?!well-known) { deny all; }

    # Фирменный цвет из админки отдаёт PHP, а не файл — без этого цвет не применится
    location = /brand.css { rewrite ^ /index.php last; }

    # Загрузки: ничего не исполнять
    location ^~ /uploads/ {
        location ~ \.(?:php|phtml|phar|html?|js|svg)$ { return 403; }
        try_files $uri =404;
    }

    location / { try_files $uri /index.php?$query_string; }

    location = /index.php {
        include fastcgi_params;
        fastcgi_param SCRIPT_FILENAME $document_root/index.php;
        fastcgi_pass unix:/run/php/php8.3-fpm.sock;   # подставьте свою версию PHP
    }
    location ~ \.php$ { return 404; }   # любые другие .php запрещены
}
```

Обязательно скопируйте из примера блоки для SEO-файлов (`sitemap`, `robots`, `rss`, …) и статики. После изменения конфигурации: `nginx -t && systemctl reload nginx`.

### Локальный запуск для разработки

```bash
php -S 127.0.0.1:8080 tools/dev-router.php
```

Это встроенный сервер PHP — **только для разработки**. На локальных адресах (`localhost`, `127.0.0.1`, `*.local`, `*.test`) `noindex` включается автоматически. Для локальной установки задайте в мастере адрес `http://127.0.0.1:8080` и отключите принудительный HTTPS (`force_https` в конфиге).

## После установки: чек-лист

1. **Войдите в админку** и откройте «Настройки → Сайт и редакция»: заполните e-mail редакции (он показывается на странице «Контакты»), название издателя, падежи города и регион.
2. **Включите 2FA** («Профиль и безопасность» в меню пользователя). Не оставляйте адрес админки `admin`.
3. **«Настройки → SEO»**: вставьте коды подтверждения Яндекс.Вебмастера и Google (файлы создаются автоматически, FTP не нужен). Проверьте, что индексация открыта.
4. **Логотип и цвета**: «Настройки → Оформление и бренд».
5. **Погода**: введите ключ WeatherAPI.com в «Настройки → Радио, погода, кино» (без ключа блок погоды скрыт).
6. **Меню и страницы**: «Сайт → Меню сайта» — отключите ненужные разделы (афиша, кино, радио, погода).
7. **Cron** (необязательно, но надёжнее) — см. [Фоновые задачи](#фоновые-задачи-и-резервные-копии).
8. **Отправьте `sitemap.xml`** в Яндекс.Вебмастер и Google Search Console (один раз).
9. Откройте «Система»: проверьте версии PHP/БД, закрытость служебных файлов, сделайте первую резервную копию.
10. Пройдите чек-лист развёртывания из `docs/SECURITY-AUDIT.md` (раздел 4).

## Файл конфигурации

Обычно `config/config.php` создаёт мастер. Образец — `config/config.sample.php`:

```php
return [
    'app' => [
        'url' => 'https://example.ru',   // канонический адрес без слэша в конце
        'key' => '…64 hex-символа…',     // секретный ключ; не меняйте после установки
        'timezone' => 'Europe/Moscow',
        'debug' => false,                // на боевом сайте всегда false
        'admin_path' => 'admin',         // адрес админки
        'force_https' => true,
        'enforce_host' => true,          // редирект www → основной домен
        'trusted_proxies' => [],         // например ['127.0.0.1'] за nginx / Cloudflare
    ],
    'db' => ['host' => 'localhost', 'port' => 3306, 'name' => 'tk', 'user' => 'tk', 'pass' => '', 'socket' => ''],
];
```

> **Ключ `app.key` шифрует секреты в базе** (AES-256-GCM). Если его потерять или заменить, сохранённые секреты (например, ключ погоды, 2FA) придётся ввести заново. Храните копию `config.php` в безопасном месте.

| **Администратор** | всё |
| **Редактор** | публиковать и править любые новости, афишу, страницы, SEO, медиа |
| **Автор** | писать новости и отправлять на проверку, править только свои неопубликованные материалы, загружать медиа |

### Как опубликовать новость

1. «Новости → Новая новость».
2. Заполните заголовок, текст, рубрику, теги (начните вводить — появятся подсказки; максимум 10), обложку.
3. Справа задайте статус: **черновик**, **на проверку** или **опубликовано**; для отложенной публикации укажите будущую дату (нужен [cron](#фоновые-задачи-и-резервные-копии)).
4. Следите за SEO-чек-листом и предпросмотром сниппета. Пустое SEO-описание создастся автоматически.
5. Сохраните. Sitemap, RSS и IndexNow обновятся сами.

### Массовые действия

Во всех списках слева есть флажки. Отметьте одну или несколько записей — внизу экрана появится **закреплённая панель**: счётчик «Выбрано: N», выбор действия («Опубликовать», «В черновики», «Удалить», «Отключить» — набор зависит от списка), кнопки «Применить» и «Снять выбор». Верхний флажок в заголовке таблицы выбирает всю страницу.
Системные записи при удалении пропускаются, используемые файлы медиатеки не удаляются.

### Меню сайта

«Сайт → Меню сайта»: переименовать, переставить (стрелки ↑↓), создать, удалить и **отключить** пункты.
* Разделы **Новости, Афиша, Кино, Погода, Радио** нельзя удалить, но можно отключить: пункт исчезает из шапки и подвала, адрес отвечает «страница не найдена», раздел выпадает из `sitemap.xml` и `llms.txt`.
* Новый пункт ведёт на страницу из раздела «Страницы» или на любую ссылку (`/путь` или `https://…`, можно в новой вкладке).

### Блоки на сайте и ссылки

«Сайт → Блоки на сайте» — это заголовки и места, где показываются группы ссылок (плитки на главной, списки в подвале, соцсети). Создайте блок, затем добавьте в него ссылки в «Ссылки и сервисы». Пустой блок на сайте не показывается; отключение блока сохраняет ссылки.

### Страницы разделов

«Контент → Страницы разделов»: для Главной, Новостей, Афиши, Кино, Погоды и Радио можно изменить заголовок (H1), вводный текст, добавить текст внизу страницы и задать SEO-заголовок и описание. Пустое поле — стандартный текст.

### Афиша

«Контент → Афиша»: список разбит на страницы по 30 событий, есть поиск по названию. Статусы: «Опубликовано», «Черновик», «Прошло».

### Медиатека

Загрузка перетаскиванием, автоматическое создание WebP/JPEG-вариантов, защита от дублей, описание (alt) для доступности. В окне выбора изображения (при вставке в статью) показывается до 24 файлов; список подгружается при прокрутке или кнопкой «Ещё», работает поиск по описанию.

### Профиль и безопасность

Меню пользователя → «Профиль и безопасность»: смена пароля, **2FA (TOTP)** с резервными кодами, список сеансов.

### Если забыли пароль администратора

```bash
php bin/reset-password.php логин
```

Скрипт запросит новый пароль (от 12 символов), завершит все сеансы и потребует смены пароля при входе.

## Настройка под своё издание

Всё делается в админке:

* **Сайт и редакция** («Настройки → Сайт и редакция»): название, слоган, описание, **тип проекта** (городской портал / газета / интернет-СМИ / другой — меняет формулировки), издатель, город в трёх падежах, регион, контакты, кинотеатр.
  В текстах страниц работают подстановки: `[[city]]`, `[[city_in]]`, `[[city_of]]`, `[[region]]`, `[[city_about]]`, `[[site_name]]`, `[[contact_email]]`, `[[domain]]`.
* **Оформление и бренд** («Настройки → Оформление и бренд»):
  * логотип для шапки и отдельный (светлый) для тёмного подвала — PNG/WebP с прозрачным фоном;
  * фавикон — одно квадратное изображение от 512×512, из него автоматически создаются `favicon.ico`, значки iOS/Android и PWA-иконки (нужно расширение GD);
  * **фирменный цвет** — шапка, кнопки, рубрики, `theme-color`; цвет надписей и оттенки ссылок подбираются автоматически (контраст WCAG ≥ 4,5), применяется и в админке;
  * картинка для соцсетей 1200×630 и короткое название приложения.
* **Радио, погода, кино**: адрес потока радио, кинотеатр и ссылки, координаты города.
* **Погода — WeatherAPI.com.** Зарегистрируйтесь на weatherapi.com, скопируйте API Key и вставьте его в настройки. Сервер запрашивает прогноз не чаще раза в 30 минут, браузер читателя к WeatherAPI не обращается. Число дней прогноза (1–14) зависит от тарифа: бесплатный даёт 3. Если погода не появилась, под полем ключа показан последний ответ API. Ссылку «Powered by WeatherAPI.com» на странице погоды не удаляйте — этого требуют условия бесплатного тарифа.
* **Ненужные разделы** (афиша, кино, радио, погода) отключайте в «Меню сайта».

## Пагинация и «Показать ещё»

Везде, где материалов много, на сайте работают **оба варианта** одновременно:

* **Номерные страницы** (`Назад / 1 2 3 / Вперёд`) — обычные ссылки; их видят поисковики, они работают без JavaScript. Для каждой страницы заданы `canonical`, `prev` и `next`.
* **Кнопка «Показать ещё»** — подгружает следующую страницу под текущим списком без перезагрузки. Без JS это обычная ссылка на следующую страницу.

| Раздел сайта | Страниц | Кнопка «Показать ещё» |
|---|---|---|
| Новости, рубрики, теги, поиск | по числу в настройке «новостей на странице» | да |
| Афиша — предстоящие | по 12 | да |
| Афиша — архив (`/afisha?past=1`) | по 12 | да |
| Главная | не нужна (фиксированное число материалов) | — |

В админке везде номерная пагинация (новости — 25, афиша — 30, медиа — 24, журнал — 50 и т. д.).

## SEO — автоматизация

Всё обновляется само при сохранении, публикации и удалении материала:

* `sitemap.xml` (индекс), страницы, новости с картинками, афиша, **Google News**;
* `robots.txt` (с `Clean-param` для Яндекса, опцией запрета ИИ-ботов и режимом «закрыто от индексации»);
* `rss.xml`, `rss-yandex.xml` (Яндекс Новости / Дзен), `llms.txt`, `manifest.webmanifest`, `opensearch.xml`, `.well-known/security.txt`;
* **IndexNow** — мгновенное уведомление Яндекса и Bing об изменённых адресах (Google IndexNow не поддерживает — отправьте ему `sitemap.xml` в Search Console один раз);
* JSON-LD: `NewsMediaOrganization`, `WebSite` + `SearchAction`, `NewsArticle`, `BreadcrumbList`, `CollectionPage` / `ItemList`, `Event`, `RadioStation`; Open Graph, Twitter Cards;
* автокартинка 1200×630 для превью, если у новости нет фото; ответ `304 Not Modified` для краулеров;
* **301-редиректы** со старых адресов; при смене адреса новости — автоматический 301, при удалении — 410; мастер редиректов и журнал 404;
* **SEO-центр**: готовность к индексации, аудит материалов, журнал IndexNow.

Принудительно пересобрать SEO-файлы из консоли:

```bash
php bin/seo-regenerate.php
```

## Фоновые задачи и резервные копии

Сайт работает и без cron, но он нужен для **публикации по расписанию**, IndexNow и очистки. Добавьте в cron (`crontab -e`) или в планировщик хостинга:

```cron
*/5 * * * * php /путь/к/сайту/bin/cron.php
0 3 * * *   php /путь/к/сайту/bin/backup.php
```

* **Резервные копии** можно делать и вручную: «Система → Создать копию». Хранятся последние 14. Файл содержит все данные, включая хэши паролей, — **храните как секрет**.
* Копируйте также папку `public/uploads/` и файл `config/config.php`.
* Восстановление: импортируйте дамп в пустую базу (phpMyAdmin или `mysql`), верните `config.php` и `uploads/`.

## Обновление

1. **Сделайте резервную копию**: «Система → Создать копию» и копию папки `public/uploads/`.
2. Замените файлы проекта новыми. **Не затирайте** `config/config.php` и `public/uploads/`.
3. Откройте любую страницу сайта: недостающие таблицы создаст `Migrator` автоматически. Вручную SQL выполнять не нужно (запасной вариант — `database/schema.sql`, он безопасен для повторного запуска).
4. «Система → Очистить кэш».
5. Для nginx убедитесь, что есть блок `location = /brand.css { rewrite ^ /index.php last; }` — иначе фирменный цвет не применится.
6. Прочитайте `CHANGELOG.md` и `docs/UPGRADE.md` — там описаны изменения конкретных версий (например, смена источника погоды на WeatherAPI.com: ключ Open-Meteo не подходит).

## Безопасность

* Пароли — Argon2id; блокировка перебора; **2FA TOTP** с резервными кодами; сессии в БД (идентификатор хранится хэшем).
* Защита от CSRF, строгий CSP **без единого стороннего источника** (кроме потока радио), HSTS, белый список HTML в редакторе.
* Безопасная загрузка файлов с перекодированием изображений, запрет исполнения кода в `uploads/`.
* Подготовленные запросы ко всей БД, шифрование секретов (AES-256-GCM), журнал действий.
* Служебные папки закрыты от веба (`.htaccess` / конфигурация nginx).
* Отчёт о проверке — `docs/SECURITY-AUDIT.md`; приватность — `docs/PRIVACY.md`.

Рекомендации: HTTPS, актуальная версия PHP, 2FA для всех редакторов, нестандартный адрес админки, регулярные копии, `debug => false`.

## Решение проблем

| Симптом | Что проверить |
|---|---|
| Белая страница или ошибка 500 | Версия PHP ≥ 8.2, нужные расширения; журнал ошибок в `storage/` и логи PHP/веб-сервера; права на `config/`, `storage/` |
| Мастер установки не открывается | Корень сайта должен быть `public/` (или работает корневой `.htaccess` и включён `mod_rewrite`); при наличии `config/config.php` мастер отключён |
| «Не удаётся подключиться к БД» | Хост, имя базы, логин и пароль; у пользователя должны быть права, включая `CREATE`; кодировка `utf8mb4` |
| Все страницы, кроме главной, дают 404 | Не работает перезапись адресов: `mod_rewrite` / `try_files` в nginx |
| Нельзя загрузить фото | Нет расширения `gd`; права на запись в `public/uploads/`; лимиты `upload_max_filesize` и `post_max_size` |
| Фирменный цвет не применяется | В nginx нет блока для `/brand.css`; очистите кэш в «Система» |
| Нет погоды | Не введён ключ WeatherAPI; нет расширения `curl`; ответ API показан под полем ключа |
| Новости по расписанию не публикуются | Не настроен cron (`bin/cron.php` каждые 5 минут) |
| Сайт закрыт от индексации | Проверьте «Настройки → SEO» и режим «закрыто от индексации»; на локальных адресах `noindex` включён всегда |
| Забыт пароль | `php bin/reset-password.php логин` |
| Меню админки не закрывается на смартфоне | Обновите страницу с очисткой кэша (`admin.css`, `admin.js`); меню закрывается по фону, крестику и Esc |
| После обновления «старый» вид | Очистите кэш браузера и «Система → Очистить кэш» |
