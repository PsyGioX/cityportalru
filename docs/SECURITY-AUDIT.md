# Аудит безопасности движка сайта

## Аудит от 8 октября 2026 (версия 1.2.0)

**Метод и границы.** Статический разбор кода (аутентификация, сессии, CSRF, санитайзер HTML, загрузка файлов, резервные копии, заголовки, новые модули этой версии), сверка стека с публичными сроками поддержки на дату аудита. **Что не делалось:** PHP-интерпретатора в среде проверки не было, поэтому ни код, ни автотесты (`tools/`) не запускались, а динамического тестирования на живом сервере не проводилось. Перед выкладкой на боевой сайт прогоните `tools/` и пройдите чек-лист в конце. Это не замена тесту на проникновение.

### Остаточные риски (принимаются осознанно)

* Администратор с правом «Настройки» может указать любой адрес потока радио — он будет разрешён в CSP (`media-src`). Доверяйте этому праву только администраторам.
* Резервные копии содержат хэши паролей и зашифрованные секреты. Хранятся в `storage/backups` (права 0600, веб-доступа нет), скачиваются только администратором; не отправляйте их по почте и мессенджерам.
* Блокировка по IP за обратным прокси работает только при верно настроенном `trusted_proxies`.
* Анимированные GIF сохраняются без перекодирования (после проверки на встроенный код); исполнение файлов в `uploads/` запрещено, отдача — с песочницей CSP.

### Чек-лист перед выкладкой 1.2.0

1. Запустите автотесты из `tools/` на тестовом экземпляре (PHP 8.3+), прогоните вход, 2FA, загрузку фото, массовые действия, отключение раздела меню.
2. Версии PHP и СУБД — не ниже указанных выше.
3. Включите 2FA всем администраторам и редакторам (настройка «Требовать 2FA»).
4. Задайте ключ WeatherAPI **заново**: ключ прежнего поставщика не подойдёт.
5. Раздел «Система»: все служебные адреса должны отвечать 403/404.

## 2. Состояние CVE и угроз на 5 октября 2026

### 2.1. PHP — **главный пункт**

* **PHP 8.1 снят с поддержки:** исправления безопасности upstream прекращены 31.12.2025. Проект поэтому требует **PHP 8.2+** (рекомендуется 8.4 или 8.5). PHP 8.2 получает только исправления безопасности — до конца 2026 года, планируйте переезд на 8.4/8.5.
* **24.09.2026** выпущены PHP **8.2.34, 8.3.35, 8.4.26, 8.5.11** — исправлены 11 CVE, в том числе:
  * CVE-2026-91765 — SOAP, неограниченная рекурсия (CVSS 7.5, High);
  * CVE-2026-91767 — OpenSSL, проверка wildcard-имён в сертификатах, чтение за границей буфера (6.5);
  * CVE-2026-91766 — обработчик HTTP-потоков при редиректах, утечка учётных данных между доменами;
  * CVE-2026-91768 — PHP-FPM, обход проверки разрешённых клиентов FastCGI для IPv6 по префиксу /96 (6.5).
* Ранее в 2026 году сообщалось о критической уязвимости SOAP (CVE-2026-6722, CVSS 9.5, по данным стороннего издания; эксплойты публиковались быстро) и XSS на странице статуса PHP-FPM (CVE-2026-6735).
* Сентябрьская уязвимость WordPress CVE-2026-87902 (локальное включение PHP-файла → RCE через `pearcmd.php`, когда включён `register_argc_argv`) показала, что опасна комбинация «включение файла по пользовательскому пути + `register_argc_argv=On`».

**Что делает проект:**
* не использует SOAP, потоковые HTTP-обёртки (`file_get_contents('http…')`) и `unserialize`; все исходящие запросы — через cURL без следования редиректам (`CURLOPT_FOLLOWLOCATION=false`) и только на фиксированные хосты;
* не подключает файлы по пользовательским путям — `include/require` только с константными путями; имена шаблонов задаются кодом;
* установщик в разделе «Проверка сервера» показывает предупреждения, если SOAP загружен, `register_argc_argv` включён, версия PHP ниже 8.2;
* `public/.user.ini` выключает `register_argc_argv` и `display_errors`.

**Что нужно сделать вам:** убедитесь, что на хостинге PHP **не ниже 8.2.34 / 8.3.35 / 8.4.26 / 8.5.11** (в панели хостинга выберите последнюю ветку), отключите расширение SOAP, если оно не нужно другим сайтам; не открывайте страницу статуса PHP-FPM наружу; ограничьте FastCGI-сокет (`listen.allowed_clients`) — не по IPv6-префиксам.

### 2.3. База данных и phpMyAdmin

* **MariaDB.** В 2026 г. закрыты CVE-2026-49261 (**CVSS 10.0**), CVE-2026-48165, CVE-2026-48163, CVE-2026-44168 (по 8.0) — выполнение команд ОС при включённом Galera/wsrep. Исправлено в 10.6.27, **10.11.18**, 11.4.12, **11.8.8** (27.05.2026); более поздние релизы (10.11.19, 11.8.9) закрывают дополнительные CVE. Ветка 11.8 — LTS до июня 2028. Проект Galera не использует, но обновите сервер до последней минорной версии своей ветки.
* **Минимальные права пользователя БД:** `SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, INDEX, DROP, REFERENCES` только на базу сайта; без `SUPER`, `FILE`, `PROCESS`, `GRANT OPTION`. (После установки `CREATE/ALTER/DROP` можно отозвать.)
* **phpMyAdmin.** Последние подтверждённые мной исправления безопасности — **PMASA-2025-1/2/3** (XSS и iconv CVE-2024-2961), закрыты в 5.2.2; актуальный релиз ветки 5.2 — **5.2.3** (багфикс). Свежих PMASA за 2026 год в доступных источниках я не нашёл — проверьте <https://www.phpmyadmin.net/security/>. Рекомендации: держать актуальную версию, закрыть доступ по IP или HTTP-авторизацией, не оставлять на стандартном адресе `/phpmyadmin`, включить 2FA phpMyAdmin, не использовать `root`.

### 2.4. Обработка изображений (загрузки редакторов)

* **libpng:** CVE-2026-25646 (исправлено в 1.6.55, CVSS до 8.3), CVE-2026-33416 (use-after-free, исправлено в **1.6.56**, CVSS 7.5), CVE-2026-34757 (**1.6.57**). Нужна **системная libpng ≥ 1.6.57** (на хостинге — свежая сборка PHP).
* **libwebp:** историческая CVE-2023-4863 исправлена в 1.3.2 — убедитесь, что версия не ниже.
* **libcurl:** в 2026 г. опубликованы CVE о повторном использовании соединений; наш код создаёт новое соединение на каждый запрос, но обновите libcurl вместе с системой.

**Что делает проект:** изображения принимают только вошедшие редакторы (публичной загрузки файлов нет); проверка размера (≤ 12 МБ, ≤ 24 Мпикс), типа по сигнатуре и MIME; файл **перекодируется** GD (EXIF/GPS удаляются, посторонние данные отбрасываются), имя заменяется на случайное; SVG и HTML запрещены; в `uploads/` отключено исполнение скриптов, выставляются `nosniff` и CSP `sandbox`.

### 2.5. Правовые риски и приватность

Проект переведён на модель **«независимое издание без сбора данных»**: нет форм, объявлений, рекламы, аналитики и cookie для читателей (см. `docs/PRIVACY.md`). Это устраняет класс рисков, связанных с персональными данными читателей (утечки, несанкционированная передача за рубеж, обязанности оператора ПДн, cookie-согласие), потому что сами данные не создаются.

Что остаётся: персональные данные **сотрудников** (учётные записи, журнал действий, IP в журнале входов) и обязанности, не связанные с ПДн читателей (авторское право, законодательство о СМИ и знаках информационной продукции, материалы, запрещённые к распространению). Применимость этих норм к вашему изданию определяет юрист. Если позже добавите форму, аналитику или рекламу — вернутся и требования по ПДн.

## 4. Чек-лист развёртывания (обязательно)

**Сервер**
- [ ] Корень сайта (DocumentRoot) указывает на папку `public/` (иначе используйте корневой `.htaccess` из архива)
- [ ] HTTPS с действующим сертификатом; в `config/config.php` `app.url` начинается с `https://`
- [ ] PHP ≥ 8.2.34 / 8.3.35 / 8.4.26 / 8.5.11, расширение SOAP выключено, `expose_php=Off`, `register_argc_argv=Off`
- [ ] Apache ≥ 2.4.69 или nginx ≥ 1.30.4
- [ ] Права: `config/config.php` — 0640, папки `storage/`, `public/uploads/` — доступны на запись только пользователю PHP
- [ ] Проверка в админке: «Система» → блок «Безопасность сервера» — все служебные файлы отвечают 403/404
- [ ] БД: отдельный пользователь с минимальными правами; доступ к БД только с localhost
- [ ] phpMyAdmin: последняя версия, не на стандартном адресе, ограничение по IP / HTTP-авторизация

**Приложение**
- [ ] Включена 2FA у всех администраторов и редакторов (и опция «Требовать 2FA»); сохранены резервные коды
- [ ] Указан e-mail редакции («Настройки → Сайт и редакция»)
- [ ] Сменён адрес админки (необязательно, но уменьшает фоновый шум)
- [ ] Настроен cron: `*/5 * * * * php /путь/bin/cron.php` и `0 3 * * * php /путь/bin/backup.php`
- [ ] Резервные копии копируются за пределы сервера (БД и `public/uploads/`)
- [ ] Включён fail2ban (или аналог) на веб-сервере и SSH; лимит запросов к `/admin/login` на уровне сервера
- [ ] Журналы доступа веб-сервера: при необходимости отключите или анонимизируйте IP (`access_log off;`)
- [ ] Папки `tools/`, `docs/`, `database/` недоступны из интернета (уже закрыта `.htaccess`; для nginx — корень `public/`)

**Регулярно**
- [ ] Раз в неделю смотреть «Журнал действий» и «Система»
- [ ] Подписаться на рассылки безопасности PHP, вашего хостинга и phpMyAdmin; обновлять в течение суток при критических CVE

## 5. Описание тестов

* `tools/security_tests.py` (69): заголовки (CSP, nosniff, frame, referrer, permissions, COOP); доступ ко всем адресам админки без входа; CSRF; SQL-пробы, включая time-based `SLEEP(5)`; отражённый и хранимый XSS; обход пути; Host-header injection; **приватность** (нет cookie, нет сторонних хостов, нет форм, нет скриптов аналитики, таблицы с данными читателей отсутствуют, просмотр не создаёт записей о посетителе); вход, фиксация сессии, флаги cookie, open redirect, блокировка перебора и защита от блокировки владельца, перечисление пользователей, политика паролей; роли и IDOR; санитайзер HTML; загрузка PHP/SVG/HTML под видом изображений, «бомбы» по пикселям, полиглот PNG+PHP; **дубли загрузок** и сохранение пропорций вариантов; исправление размеров картинок в тексте; условный GET (304).
